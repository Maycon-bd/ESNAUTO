1. Visão Geral da Pesquisa
Este documento descreve o processo metodológico de implementação do TFC, que constitui uma pesquisa aplicada experimental. O objetivo central é investigar se diferentes distribuições de probabilidade na inicialização dos pesos de entrada (Win) de Redes Neurais de Estados de Eco (ESN) afetam o desempenho preditivo sobre séries temporais financeiras da PETR4, quando combinadas com otimização de hiperparâmetros por Algoritmos Genéticos (AG) e pré-processamento via Fator de Ajuste.
A implementação será realizada integralmente em linguagem R, aproveitando sua vocação para computação estatística, manipulação de séries temporais e visualização de dados.
2. Fluxo Geral da Implementação
A pesquisa está organizada em cinco etapas sequenciais, conforme o fluxo abaixo. Cada etapa depende da conclusão da anterior, garantindo rastreabilidade e reprodutibilidade dos experimentos.
3. Etapa 1 — Coleta e Pré-processamento dos Dados
3.1 Fonte dos dados
A base de dados utilizada é a BOVDB (Cardoso et al., 2022), que contém séries históricas de preços de todas as empresas da B3 de 1995 a 2020. Para este trabalho, serão utilizados os dados da PETR4 (Petrobras ON), ativo de alta liquidez e amplamente estudado na literatura nacional (Timbó et al., 2016).
As variáveis extraídas da base serão: preço de abertura, preço de fechamento, preço máximo, preço mínimo e volume negociado. A variável-alvo da predição é o preço de fechamento ajustado.
3.2 Aplicação do Fator de Ajuste
Eventos corporativos como desdobramentos de ações (splits), grupamentos (inplits) e distribuição de dividendos geram descontinuidades artificiais nas séries históricas de preços. Se não corrigidas, essas descontinuidades podem ser interpretadas pelo modelo como movimentos reais de mercado, introduzindo ruído sistemático no treinamento.
Para eliminar essas distorções, será aplicado o Fator de Ajuste proposto por Cardoso et al. (2022), calculado pela relação entre o preço de fechamento do dia anterior ao evento e o preço de abertura no dia em que o evento entra em vigor:
Fator = Preço_fechamento(t-1) / Preço_abertura(t)
O fator é aplicado retroativamente sobre toda a série histórica anterior ao evento. Serão comparados os resultados com e sem a aplicação do Fator de Ajuste, testando diretamente a quarta hipótese do trabalho.

4. Etapa 2 — Implementação das ESNs em R
4.1 Arquitetura da ESN
A Echo State Network (ESN) pertence ao paradigma da Computação de Reservatório (Reservoir Computing). Sua principal característica é que os pesos internos do reservatório são gerados aleatoriamente e permanecem fixos durante todo o treinamento. Apenas os pesos da camada de saída (Wout) são ajustados, por meio de regressão linear regularizada (Ridge Regression), o que torna o treinamento extremamente rápido e matematicamente estável em comparação com LSTM e GRU.
* A inicialização de Win é a variável experimental central deste TFC. Quatro distribuições serão testadas.

4.4 Implementação em R
O esqueleto de código para uma variante ESN em R será estruturado da seguinte forma:
# Pacotes necessários
library(reservoirnet)  # ou implementação manual
library(Matrix)        # operações esparsas

# Função de inicialização do reservatório
criar_esn <- function(N, rho, sparsity, leak, dist = "normal", nu = NULL) {
  # Gerar Win conforme distribuição escolhida
  Win <- switch(dist,
    "normal"  = matrix(rnorm(N * n_inputs), N, n_inputs),
    "t"       = matrix(rt(N * n_inputs, df = 5), N, n_inputs),
    "t_assym" = matrix(rst(N * n_inputs, xi=0, omega=1, alpha=1, nu=5), N, n_inputs),
    "ged"     = matrix(rged(N * n_inputs, nu = nu), N, n_inputs)
  )
  # Gerar W (reservatório) e escalar pelo raio espectral
  W <- Matrix(rnorm(N * N) * (runif(N*N) > sparsity), N, N, sparse=TRUE)
  W <- W / max(abs(eigen(W)$values)) * rho
  list(Win=Win, W=W, leak=leak, N=N)
}

# Função de treinamento (Ridge Regression)
treinar_esn <- function(esn, X_treino, y_treino, lambda) {
  estados <- coletar_estados(esn, X_treino)
  Wout <- solve(t(estados) %*% estados + lambda * diag(ncol(estados)),
                t(estados) %*% y_treino)
  list(esn=esn, Wout=Wout)
}
5. Etapa 3 — Otimização por Algoritmos Genéticos
5.1 Motivação
A escolha manual de hiperparâmetros para uma ESN é inviável dado o tamanho do espaço de busca — cinco hiperparâmetros contínuos com intervalos amplos. Os Algoritmos Genéticos (AG) são métodos de busca bioinspirados que exploram o espaço de soluções de forma eficiente sem exigir que a função objetivo seja contínua ou derivável (Millea, 2014). Deng et al. (2022) e Araújo et al. (2024) demonstraram empiricamente que AGs são eficazes na otimização de ESNs em séries temporais.

5.3 Função de fitness
A função de fitness avalia cada indivíduo (conjunto de hiperparâmetros) treinando uma ESN com esses parâmetros no conjunto de treino e avaliando o erro no conjunto de validação. Serão utilizadas duas funções de fitness separadas — MAE e RMSE — replicando a metodologia de Araújo et al. (2024), o que permitirá comparar qual métrica como fitness produz melhor generalização no teste.
# Função de fitness para o AG
fitness_esn <- function(hiperparams, dist, X_treino, y_treino, X_val, y_val) {
  rho      <- hiperparams[1]  # raio espectral
  sparsity <- hiperparams[2]  # esparsidade
  leak     <- hiperparams[3]  # leak rate
  N        <- round(hiperparams[4])  # tamanho reservatório
  lambda   <- hiperparams[5]  # regularização

  esn    <- criar_esn(N, rho, sparsity, leak, dist)
  modelo <- treinar_esn(esn, X_treino, y_treino, lambda)
  pred   <- prever_esn(modelo, X_val)

  mae <- mean(abs(pred - y_val))  # ou RMSE
  return(-mae)  # AG maximiza — negativo do erro
}
5.4 Implementação em R
library(GA)

resultado_ag <- ga(
  type     = "real-valued",
  fitness  = function(x) fitness_esn(x, dist="ged", ...),
